# reference-crud — 唯一范式

**照这个写。** 其余两个示例（`graph-modeling-studio`、`workbench-kit`）是历史遗留，违反现行 UI 契约，只作为「不要这么写」的对照保留。

本示例的业务是一次性的（服务工单），但**结构和技术选型是通用的**：主面板 + 列表工作区 + 详情抽屉。

## 它演示了什么

| 契约条款 | 本示例的做法 |
|---|---|
| §6 只允许 SDK 组件 + Tailwind 原子类 | 全部用 `@appthen/vibe-workspace/components`，**0 个独立 CSS 文件** |
| §6.2 不新增独立 `.css` | 整个扩展示例没有一行 CSS，也没有内联 `style` |
| §9 字号下限 12px | 只用 `text-xs`(12) / `text-sm`(14) / `text-base`(16) / `text-xl`(20) |
| §1 控件默认档 | 一律吃平台默认 32px，需要小用 `size="sm"`，不写高度覆盖 |
| §7.2 主面板三问 | 首屏有真实计数、主操作「新建工单」在标题下、无假入口 |
| §7.3 主操作不贴底 | 主操作紧跟标题；贴底只放「工单分类与字段设置」 |
| §7.4 列表不占满首屏 | 主面板只放「待受理 + 待验收」的前 4 条，完整列表在 editor view |
| §6.4 状态不用满色块 | 状态一律 `StatusChip tone=... appearance="dot"` |
| 五态齐全 | 列表有骨架 / 空态（带清空筛选 CTA）/ 正常；抽屉有保存反馈 |
| 容器宽度适配 | 用 `@min-[420px]:` 容器变体，不用视口断点（分屏时视口宽度会骗人） |

## 三条最容易写错的地方

1. **`SimpleSelect` 默认 `w-full`**。放进 `flex` 横向布局必须包一层定宽容器（`<div className="w-[140px]">`），否则每个下拉各占一整行。
2. **抽屉在 portal 里**，容器查询查不到它。抽屉内部的宽度/布局适配只能用视口断点（`sm:`），不能用 `@min-[...]`。
3. **不要把主面板写成入口菜单**。§7.2 的 Q1/Q2 是必过项：首屏得有真实数字和一个直达动作，否则就是不合格。
