# B2B UI/UX Reference

这是一份面向企业管理、运营后台、专业工作台和数据密集型扩展的**可选设计资源**：既包含页面结构范式，也包含一套"数据驾驶舱"视觉表达语言。它用于帮助 Agent 识别用户期待的产品方向并落地实现；它是推荐规范之一，不是所有扩展都必须遵守的模板。

## 何时加载与遵循强度

当需求包含以下信号时加载本资源：企业管理、客户/项目管理、组织、权限、审批、配置、运营后台；长期重复处理业务数据；搜索、筛选、排序、分页、批量操作、状态追踪；用户强调工作台、控制台、效率、信息密度。

**遵循强度由用户意图决定：**

- **用户显式点名使用 B2B 规范**（如"用这个扩展技能开发，含 b2b 规范"）：视为强匹配。结构范式与视觉表达**都要遵循**，实现后对照第 6 节自检，不确定的细节再问。
- **需求信号明显但用户未点名**：结构范式优先采用；视觉表达层至少做到"信息有色彩层级、状态有色、数字有排版"，并在方案说明中提一句采用了 B2B 风格。
- **匹配度不确定**：向用户询问风格定位，给出选项，例如：A. 专业管理工作台（紧凑素雅）；B. 数据驾驶舱（本资源的完整视觉表达，参考常见运营仪表盘：品牌色贯穿、统计卡、图表、状态标签）；C. 轻量品牌页。
- **明显不匹配**（小游戏、创作工具、媒体画布、强品牌表达页）：不套用。

以下实现统一使用 Workbench 主题 token（`--portal-*`、shadcn 语义层、`charts.*`），**不写死 hex**；下文颜色均指"主题 token 的语义角色"。

## 1. 视觉表达：数据驾驶舱语言

B2B 数据页面的"高级感"来自**有控制的色彩层级 + 数字排版 + 可视化**，而不是黑白灰加边框。结构范式决定放什么，本节决定长什么样。两者必须同时到位。

**视觉锚点图**：[b2b-dashboard-reference.png](b2b-dashboard-reference.png)——实现前先看这张图，它就是本节的目标效果（工作台/仪表盘形态的完整示范：品牌色贯穿、统计卡、状态 tag、图表组合、移动端适配）。

### 1.1 品牌主色贯穿

主色（`--portal-primary`）不是只给主按钮用，它是页面的视觉骨架：

- 主 CTA 按钮、选中态（左侧色条或浅主色底）、链接与"查看更多"
- 图表主色（柱状图主系列、折线、环形进度外环）
- 进度条填充、当前页码、输入框 focus 边
- 图标块的浅底 + 主色图标（见 1.3）

### 1.2 KPI 统计卡（首页与概览的标准件）

每组关键指标做成统计卡组，单个卡片结构固定为四层：

```text
[图标块]  [标签 12px muted]
          [大数字 20-24px tabular-nums] [单位 12px muted]
          [同比/趋势：↑ 8.2% 绿 或 ↓ 3.1% 红，12px]
```

- 图标块：36-40px 圆角方块，浅色功能色底（主色/成功/警示/危险的 10-14% tint），内放同色系图标；同组卡片轮换不同功能色，形成彩色节奏。
- 大数字用 `font-variant-numeric: tabular-nums`；趋势上涨用成功色/下跌用危险色（业务语义相反时颠倒，如成本）。
- 3-4 张一组等宽排布；卡片 `bg-card` + `border-border` + 小圆角，不要加粗边框。

> 实现约定：本节与 §1.4/§1.6 的视觉公式以 cva variant 承载（`tone="primary|success|warning|danger"`），不写成扩展 CSS 规则，见 UI-CONTRACT.md §6。

### 1.3 快捷入口网格

高频功能入口用 2×2 或 4 列图标块网格：图标块（浅功能色底 + 图标）+ 下方 12px 标签。这与 KPI 卡的图标块同一语言，形成页面一致性。

### 1.4 状态标签与待办列表

- 状态/分类用**浅底深字 tag**：`--portal-danger-bg` 底 + `--portal-danger` 字（警告、成功、主色同理）；同屏 tag 颜色种类控制在 3-5 种。
- 待办/任务列表行：左侧状态 tag + 标题 + 元信息（负责人/时间，12px muted）+ 行尾轻量操作按钮；行 hover 用 `--portal-fill`。
- 优先级用文字 tag（加急/紧急）+ 色点，不只靠颜色。

### 1.5 图表：主题化 + 组合套路

- 一律走主题 chart tokens（`charts.blue`/`charts.green`/`charts.red` 等），随主题联动。
- 常用套路：**柱状图 + 折线组合**（双系列对比）、**环形进度**（中心放大号百分比数字，外环主色或功能色）、**横向进度条列表**（每行：名称 + 条 + 右侧数值）。
- 图表卡都带卡片头：标题 + 右侧"查看更多"或时间范围切换。
- 图表库跟随 Workbench 既有方案，不要自行引入新的图表依赖。

#### 1.6 素色与渐变卡片底（tint cards）

同组卡片用不同功能色的"淡雅 tint 底"制造彩色节奏（参考常见运营仪表盘的统计卡区），公式：

```css
/* 底：135° 渐变，功能色 10% → 3%，以 --portal-card 为基底 */
background: linear-gradient(135deg,
  color-mix(in srgb, var(--portal-primary) 10%, var(--portal-card)),
  color-mix(in srgb, var(--portal-primary) 3%, var(--portal-card)));
/* 边：同色 18% tint */
border: 1px solid color-mix(in srgb, var(--portal-primary) 18%, transparent);
/* 图标块加深一档（14%）与卡底形成层次 */
```

规则：
- tint 强度 4%~14%，渐变两端差 ≤10%；禁止高饱和实底（品牌实底 CTA 卡除外，文字用白色）；
- tint 上的文字仍用 `--portal-ink` / `--portal-body` / `--portal-sub`，**不放白字**；
- 以 `--portal-card` 为 mix 基底 → 深色主题自动得到深底淡 tint，无需单独适配；
- 同组卡片轮换不同功能色（主色/成功/警示/危险），一组 3-4 张；页面其余卡片保持白卡，避免满屏都 tint；
- 页头/hero 区可用更淡的主色渐变（8%→2%）。

### 1.7 页面骨架（桌面端模块首页）

```text
页头：问候/标题 + 主 CTA（主色按钮）
第一行：KPI 统计卡组（1.2）
第二行：待办/任务列表（1.4） + 可视化卡（1.5，环形或柱线）
第三行：快捷入口网格（1.3） + 横向进度条列表（1.5）
```

**移动端 = App 主页面，头区一行化（强制）**：移动端底部 Tab 已标明模块身份，
扩展自己的桌面页头（标题 + 副标题 + CTA 渐变 hero 卡）不允许照搬占掉首屏——
头区压缩为**单行**（模块名 + 关键计数 + 紧凑 CTA，总高 ≤36px），去掉渐变底与
副标题行，数据从第一屏开始：

```css
@media (max-width: 768px) {
  .module-home__hero { padding: 0 2px; margin-bottom: 8px; background: none; border: 0; }
  .module-home__cta { height: 28px; padding: 0 9px; font-size: 11px; }
}
```

KPI 组 2×2、待办列表、图表卡顺次单列；tag、图标块、数字排版规则不变。
判断口诀：**"桌面首屏先给语境（hero），移动首屏直接给数据（KPI）"**。

### 1.8 同一思想、不同构图（防模板化）

本节是**思想清单，不是固定模板**。同一规范在不同模块必须长出不同的构图，否则所有扩展长得像同一个。构图由模块的核心叙事决定：

| 模块叙事 | 构图示例 |
| --- | --- |
| 管理型（客户/资产台账）："库有多大、质量如何" | KPI 统计卡组 2×2（tint 渐变）+ 健康度环形 + 状态 tag 待办 |
| 运营型（营销/活动）："在跑什么、跑到哪了" | 主指标渐变横幅（单大数字 + 迷你指标行）+ 活动进度列表（icon 块 + tag + 进度条 + 百分比）+ 双列入口块 |
| 监控型（告警/巡检）："哪里在烧、要不要处理" | 告警优先的待办流 + 严重度色阶 + 时间线 |

复用的只有视觉语言：主色贯穿、图标块 tint、大数字排版、浅底深字 tag、进度/环形可视化、移动端头区一行化。**禁止**把某个模块的页面结构复制到另一个模块；新模块先问"它的核心叙事是什么"，再从上表选或发明构图。

## 2. 结构范式（配合视觉表达使用）

### 2.1 模块首页先交付价值

Sidebar 是模块首页：承载 KPI 摘要、待处理事项、高频入口、状态分布——不要退化成只有"打开列表"按钮的导航壳，也不要把所有数据塞进首页。

### 2.2 持续处理进入工作区

连续浏览、筛选、排序、分页、批量处理放独立 Editor 工作区；保留筛选与选中上下文；表格/卡片/看板/时间线按任务选择，不固定组合。

### 2.3 详情与编辑保持上下文

单条详情与中等编辑用 Drawer（保留列表上下文）；少字段快确认用 Dialog；多步骤长流程升级 Editor。

### 2.4 桌面与移动各自服务任务

桌面强调比较、批量、常驻筛选、高密度；移动强调快速查看、单列、关键字段、即时行动。同一数据可换呈现，重要操作两端都可达。

### 2.5 状态、待办和行动闭环

状态在列表/详情/首页一致；待办与异常放显眼位置；空状态带下一步 CTA；失败可重试；危险操作有确认与影响说明；不只靠颜色表达状态。

## 3. 采用前自检

1. 用户显式点名 B2B 了吗？点名则本资源按强匹配执行。
2. 页面有 KPI 统计卡、状态 tag、至少一处可视化吗？（数据密集页三件套）
3. 主色是否贯穿（CTA/选中态/图表/进度/图标块），还是只有黑白灰？
4. 数字有排版（大数字 tabular-nums + 单位 + 趋势）吗？
5. 颜色是否全部走主题 token（无写死 hex）？
6. 结构范式与视觉表达是否同时到位——只做到前者就是"素"。
